# 通用输入法接入边界（设计中，未实现级证明）

本线只负责 UI Rust 的输入法契约、后端适配与相关验证，不实现 OS 输入服务或语言/Workbench 业务。用户要求框架自身采用宽松许可，因此撤销 Fcitx 5 / fcitx5-rime。Keyman 18.0.255 的 MIT Core 是通用键盘规则处理后端，librime 1.17.0 的 BSD 核心是中文引擎候选；Core 库成功编译不代表完整 Keyman 平台系统、候选服务或 Jasper 输入法已经接通。

## 已核对的真实接口差异

| 接口 | 实际单位/所有权 | 接入义务 |
|---|---|---|
| Scintilla 文档位置 | 编辑接口主要采用文档字节位置；另有显式 UTF-16 相关 API | UTF-8 输入配置下，字节偏移不能直接接收 Unicode 标量数或 UTF-16 代码单元数 |
| Keyman `km_core_actions.code_points_to_delete` | 上游明确为 Unicode codepoints，不是 codeunits | 从同一版本的周边文本尾部按标量换算为有效 UTF-8 删除边界，处理上下文不足和超限 |
| Keyman `output` / `deleted_context` | `km_core_usv` Unicode 标量序列；输出为零终止串 | 有界复制、验证标量、明确 U+0000 表示限制，不用无界扫描处理不可信长度 |
| Keyman `km_core_state_get_actions` | 借用状态中的动作结果；下一次状态修改/事件处理使其失效 | 在再次进入引擎前复制所需结果；不跨线程/回调保留裸指针 |
| Rime `RimeComposition` | `char* preedit` 加有符号 length/cursor/selection 字段 | 固定版本 rime_api_impl.h 从 std::string.length() 及 composition.cc 的字节长度/子串位置构造；按 UTF-8 字节映射，仍须校验有符号转换、范围和字符边界并做中文/emoji 对照 |
| Rime context/commit | `get_context/free_context`、`get_commit/free_commit` 配对 | 按 data_size 版本契约初始化，复制有效内容后配对释放，不能混用两种释放函数 |

Keyman 内部 API 由其版本管理，不冻结为 Jasper 公共 API。现有 Jasper `CompositionEvent` 仅包含 text/start/end，没有预编辑开始、提交、取消阶段，也没有输入会话身份；当前类型不足以承诺跨引擎输入法服务。

## Rust 接入前的强制语义

- 同一事件明确选择宿主系统 IME 或内嵌引擎，不能重复消费、重复提交。
- 上下文关联应用/会话、编辑文档及焦点代数；延迟结果须重新检查归属与编辑版本。场景 NodeId 仅 u64，可复用，不足以单独证明原输入目标仍存活。
- 焦点切换、文档关闭、引擎切换及资源退役先失效旧上下文；旧预编辑与候选清除，迟到回调不能提交到新目标。提交或取消的选择必须是显式策略。
- 引擎产出的删除与插入按同一文档版本原子应用；转换失败时不部分修改。预编辑与最终提交分开管理，不把每次候选变化写成正式输入。
- 候选窗口/光标几何由 UI 宿主展示，语言引擎不自行创建平台窗口；无 GPU/系统字体的宿主同样走 UI 的软件渲染与注入字体能力。
- 密码/敏感字段显式声明学习、周边文本与持久化策略；不能把其他应用的上下文或共享用户词库状态静默带入。
- 先限定单一 UI 执行上下文，未经上游线程安全依据不共享可变原生状态；若后续出现生产并发路径，Loom 必须实际映射该路径。

## 尚未完成的验证义务

以上为接入规格和风险登记，不是已证明结果。自有 Rust 的索引转换、会话生命周期、结果归属/失效、资源释放及原子编辑都须分别有 Verus + Z3 → Proptest → Miri → cargo-fuzz → Kani → Loom 证据。第三方原生库单独记录信任边界、版本/源码/编译选项/许可/动态依赖；不以编译成功或上游测试替代自有 Rust 验收。每轮正式实现同时补一部分旧文本/输入代码；原双键 Kani 义务继续保持未完成。

## #13 评审补充：公共文本/输入能力的归属（2026-10-24）

评审来源：[公共文本与输入基础设施下沉](https://github.com/DarkMagier/jasper-internal/issues/13#issuecomment-6384584040)。这是一项长期架构评审输入，不代表已有实现或新增跨项目授权；本线继续只修改 UI Rust 与相关验证/文档，不接管公共服务、终端或内核实现。

UI 是公共契约的消费者，不应成为 Unicode 索引、文档事务与通用输入会话的永久唯一所有者。公共协议候选 TextDocument / TextEditTransaction / TextInputSession / InputEngine / Candidate / Preedit 应独立于 Scene、Skia、Scintilla 与 Keyman/Rime 私有类型；这些名称仅为职责候选，尚未冻结公开 Rust API 或包名。UI 接口只负责焦点/目标身份映射、图形候选视图、编辑视图、指针捕获与图形宿主适配。共享核心不得共享不同应用/文档的会话状态；无 GUI/GPU/系统字体的契约验收须由公共核心工作线在未来负责，本线保留可注入接口及消费者测试。

Scintilla、Lexilla、Keyman、librime 的长期退出条件应包含能力覆盖、相同行为语料、状态/索引/事务隔离、数据与许可证、跨消费者验证，以及性能基线；仅增加 Rust 包装或改名不算替换。本线目前只具备源码构建与有限原生实验，不满足退出条件。Skia 保持可替换绘图后端，其是否自主替换另行评估，不能与上述编辑/输入组件的退出目标混同，也不据此提前做 Canvas 或 OS 接入。

当前实施仍先处理捕获取消与输入身份/生命周期，再推进真实编辑/输入纵向闭环；公共核心的实现归属需要跨线契约协作，不能在本 UI 项目内自行扩大职责。已有 UTF-8/UTF-16/标量/字素边界、版本与焦点代数、取消和旧结果拒绝要求继续有效。

## 2026-10-24 15:42 UTC：实际桌面生产端存在坐标语义冲突（待修复）

源码审计发现：`input.rs` 将 CompositionEvent.start/end 注释为编辑器文档字节偏移；但 `DesktopInput::ime` 直接转发 winit `Ime::Preedit` 的预编辑文本 cursor，并在 None 时写成 `0..text.len()`，函数根本没有当前文档/选区。因此不能直接把该产物接到按文档范围检查的 `admit_composition`。反例：空文档、预编辑“ni”、cursor 0..2；预编辑局部区间有效，文档范围无效。None 被替换为整段也丢失宿主原有“无光标位置”信息。

### 2026-10-24 17:32 UTC：Skia Paragraph 选区索引接入约束（源码核查，未验收）

固定依赖 `skia-safe/skia-bindings 0.153.3` 的 Rust `paragraph.rs:86–102` 将
`Range<usize>` 经 `try_into().unwrap()` 传入原生 unsigned 参数；不能把任意宿主
usize 直接送入此接口，否则超出参数表示范围可 panic。原生
`modules/skparagraph/src/ParagraphImpl.cpp:802–845` 在 `getRectsForRange` 内调用
`ensureUTF16Mapping()`，通过 `fUTF8IndexForUTF16Index[start/end]` 转为内部 UTF-8
位置。因此该入口的范围单位为 UTF-16 代码单元，不是 Scintilla 的 UTF-8 字节，
也不是文档字素索引。源码还会调整到字素边界，不能把返回矩形反推为原始编辑范围。

UI 接入须消费公共文本契约提供的、对应同一文档版本的索引转换结果，先检查长度、
有序性、边界及 unsigned 可表示范围，再调用第三方；不能将 winit 预编辑局部范围、
文档替换范围、Skia 选区范围直接互换。公共转换实现不在本 UI 任务中另造。
目前实验只查询 ASCII `0..6`，没有验证非 BMP 代理对、组合字素、RTL 命中测试，
也没有完成光标/选区到真实编辑事务的闭环；这些仍是未完成验收项。

本次仅核查 VM 中实际固定依赖源码，没有执行编译或重测试，也不新增形式化通过声明。

## 最新替换契约（用户裁决，2026-10-24）

Scintilla/Lexilla、Keyman/Rime 均为暂用后端，必须可以逐个关闭和移除。
不将上游对象、裸指针、消息编号、私有字符串或索引单位暴露给 UI 公共调用者。
只确定 jasper.ui.*；下列为职责契约，不冻结包名或公开类型名。

| 暂用后端 | UI 自有边界 | 后续替换与回退验收 |
|---|---|---|
| Scintilla | 文档快照、修订号、有效 UTF-8 范围、原子编辑请求/结果；文档所有权由提供者持有 | 同一初始文档及编辑序列对照内容、选区、修订与撤销；拒绝/失败不能留下部分修改；替换后移除原生构建 |
| Lexilla | 指定文档修订上的样式跨度；与编辑提交解耦 | 对照相同语言语料；过期跨度丢弃；停用高亮仍能编辑，词法器不能修改文档 |
| Keyman | 复制并校验后的预编辑、候选及提交动作；按会话归属接入 | 同一键序列和周边文本对照；取消与重开隔离；替换后移除 Core 状态及 FFI |
| Rime | 同上；词库/用户数据由宿主注入、按应用隔离 | 中文/emoji/候选选择语料对照；词库迁移单列，不把引擎私有数据当公共持久化格式 |

切换顺序：先失效旧票据与预编辑/候选，再请求旧后端取消并释放状态，
最后为新后端建立新代数；迟到回调不得复活旧会话或修改新目标。
回退也必须新建会话，不复用旧引擎指针、回调、候选句柄或未提交状态。
差分模式的影子后端只能比较结果，不得重复提交、学习或写用户词库。
关闭后端能力应显式返回不可用；不能静默把未完成的事务变成成功。

以上目前是必须遵守的契约，**不是 Rust 适配已完成或验证通过**。
输入归属/原子性/生命周期的自有代码仍须完整六阶段；第三方专项异常登记后延期，
不再纠缠 Skia 私有编码。主线仍为真实文档提交与 UI 编辑/输入装配。
