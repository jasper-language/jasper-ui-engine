# 路线图（原型 → 可用）

> v0.1 是执行底座原型；API 会改。阶段只表示依赖顺序。系统内置 UI 与应用自带 UI 是一等目标，系统桌面依赖此底座。
> 数学形式化证明是关键路径交付门槛，贯穿所有阶段；现有测试不能替代证明，见 [verification.md](verification.md)。

## 当前首批执行（2026-10-23）

1. 核实能力、修正文档、登记证明义务和宿主边界。
2. 修复场景版本耗尽并验证版本内核；事务/解码/资源义务继续保持待证明。
3. 从统一文字布局对象和宿主字体注入入手，接通软件文字绘制。
4. 接真实编辑/IME、焦点、无障碍与按需帧循环。
5. 用真实 Jasper 设置页验证风格切换状态保持；内置系统接口从第 1 步参与设计，不等到最后移植。

以下版本章节保留能力分组，不代表系统宿主或证明可以延后才考虑。

## 开发策略变更：先复用成熟部件，再以验证过的 Rust 逐步替换（2026-10-24）

用户明确要求：UI 范围内能直接复用 Chromium/Chrome 生态成熟部件的，先复用以完成功能；后续自上而下用严格验证的 Rust 实现逐步替换。此策略优先于此前继续自研 Canvas/光栅器的排程。Canvas 暂用独立 Skia，通过 Rust 绑定接入，不为取得绘图能力搬入整个浏览器，也不再扩展自写光栅器。现有代码保留作行为对照，不据此决定未来公开包名。

交付分两条事实线：功能可用与自有 Rust 验证状态分别记录。暂用第三方允许作为明确未证明的实现依赖，不必先证明其全部内部再接入；这不构成第三方正确性的数学证明。自有新增/修改 Rust 接入与后续替换仍须满足 Verus + Z3 → Proptest → Miri → cargo-fuzz → Kani → Loom 的原门槛，未通过不能宣称完成。每轮继续为适量旧代码补证，但不能以补证切片数量代替 UI 功能闭环进展。

接入时登记精确版本、来源与许可、调用接口、构建依赖、宿主支持和信任边界。UI 自有契约隔开后端，第三方类型不成为 Jasper 对外语义；记录行为差异并保留回退。逐步替换时以同一契约和真实行为对照验收，不一次性重写整套依赖。

优先顺序调整为：明确 UI 功能缺口和可复用部件 → 接通首个可运行的 Skia 软件绘图/文字切片 → 将自有资源与宿主契约接入 → 扩展完整交互和无障碍。Skia 在 jasper-os 的工具链、字体/资源注入、内存与系统服务接缝需独立验证；普通桌面平台可用不能冒充系统内置宿主已支持。不强制核心依赖 POSIX、GPU、winit 或系统字体，不接管 OS 内核/语言/业务。

当前只是策略和排程变更，尚未添加 Skia 依赖或完成主渲染路径替换。既有 tiny-skia 与自写后端继续按实际代码状态登记，不能把选型决定写成已集成。

## 最新排程裁决：只接通绘图，Canvas 最后做（2026-10-24）

用户明确：Skia 接上即可，Canvas 放最后。不再以 Canvas 完整能力、专项替换或继续扩展光栅工具作为当前主线。先完成必要的成熟绘图库接缝，随后优先其他 UI Rust 框架工作（宿主/资源生命周期、输入归属与取消、文本及无障碍等）；Canvas 专项和完整替换最后安排，不因其未完成阻塞其他 UI 工作。自有 Rust 正式交付的验证门槛不变，第三方暂用信任边界不变，3D 不进入本线。

当前实际进展：隔离 Skia 实验已消费真实 Scene→Taffy layout→paint→UiBatch encode/decode；无字体样例为三布局节点、十条 PaintOp、188 字节，CPU 读回和四像素检查、非法裁剪/文字拒绝通过。显式宿主字体样例为四布局节点、十一条 PaintOp、218 字节，可绘制固定 Latin 标题，仍未完成通用文字栅格化/塑形验收；图像与源快照见 evidence/skia-cpu-probe。尚未实现正式默认 RenderBackend 接入或验收，不把实验标记为生产完成。后续只补最低限度接入，不扩张该实验为完整 Canvas 产品。


## 最新排程裁决（2026-10-24 12:00 UTC，覆盖此前宿主实装排期）

用户明确：jasper-os 实际接入安排在 Canvas 之后。当前顺序为 UI Rust 主线（指针捕获取消、输入归属/生命周期、编辑及通用输入法接入）→ Canvas 接入与补齐 → jasper-os 对接。此时只维护系统宿主接口和可移植性约束，不做 jasper-os 集成，不修改其内核或排期。Keyman MIT / librime BSD 方案、Scintilla/Lexilla 暂用策略及自有 Rust 完整六阶段门槛不变；Fcitx 5 与 fcitx5-rime 不恢复。

## Canvas 选型裁决（2026-10-27）

用户明确：Canvas 选用现成的 Rust 方案，不投入大量资源自研。Canvas 改用 **Vello**，经 Blitz 已在用的 `anyrender` 画进同一场景（CPU：`vello_cpu` / `anyrender_vello_cpu`；GPU：`vello_gpu`），**取代**此前「暂用独立 Skia」的方案。Skia 实验与 `canvas-tiny-skia` 只作行为对照，不再投入。Canvas 仍排在最后，只做薄契约层（Canvas 2D 语义 → kurbo/peniko 路径、画刷与变换），不自写光栅。

截至 2026-10-27 未找到可直接复用的独立「Canvas 2D on Vello」库；实现时以 Servo canvas 模块的 Vello CPU 后端作行为参考，只对照语义，不复制代码（该模块为 MPL-2.0）。预计 1–2 个切片。本段为选型与排程变更，尚未添加 Vello Canvas 依赖或实现任何 Canvas 绘制路径。
