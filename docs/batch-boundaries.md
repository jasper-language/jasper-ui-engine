# UI 更新、绘制与宿主边界（草案）

## 三种职责

| 职责 | 内容 | 当前实现 |
|---|---|---|
| UI 语义更新 | 节点/样式/文本/语义/资源引用，基础与目标版本，事件身份 | ScenePatch 是 Rust 内部原型；跨语言协议尚未实现 |
| 绘制批 | 布局后的绘制指令；软件/GPU 后端执行 | UiBatch/JUEB v1 编码 PaintOp |
| 传输信封 | 会话/窗口归属、epoch/序号、能力、ACK、背压与上限 | 尚未实现 |

此处是职责说明，不冻结新的公开类型名。不能把当前 PaintOp 当成 DOM/SSR 的完整语义，也不能由绘制批自动推导组件状态或无障碍树。语义更新、绘制格式和传输可以分别版本化；JUEB v1 仍保留当前含义。

## 宿主

- 系统内置：UI 服务提供执行/资源/呈现能力，系统桌面与应用消费同一 UI 语义；应用不重复携带渲染器，引擎不另造系统合成器。
- 应用自带：窗口/字体/输入/呈现由平台适配，winit/softbuffer 仅是其中一种实现。
- Web：浏览器后端消费共同语义，不要求 Rust 原生渲染器。

系统内置宿主是一等目标。软件渲染/字体加载/资源引用必须可通过宿主接入，不能假设 POSIX、系统字体目录、GPU 或 winit 存在。当前代码使用 std，可选真实文本还启用 fontconfig；不据此宣称无 POSIX 或 no_std 平台已可用。

## 待实现的最小约束

- 会话/窗口/资源归属和代际检查；应用退出、撤权、断连后引用失效。
- 收到、校验、场景应用、呈现分别确认；错误不冒充成功。
- 非法/陈旧更新不半应用；版本耗尽拒绝非空更新，空批不推进版本但仍校验期望版本。
- 有界队列和独立资源额度；可合并指针 Move，不能任意丢弃 down/up/cancel/文本提交。
- 恢复时用 epoch 与快照重同步，不把旧事件应用到新树。
- 权限、Surface、输入和 IPC 由真实系统宿主提供；未确认的接口保持待确认，不凭空定义已实现能力。

UI 关键不变量的数学形式化证明为交付门槛，见 [verification.md](verification.md)。本草案不是已实现协议，也不是证明产物。
