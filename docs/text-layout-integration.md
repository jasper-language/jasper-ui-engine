# U1：共享文本布局接入切片（未实施、未验收）

2026-10-24 17:52 UTC。仅限 UI Rust 消费文本布局和字体资源；不实现公共文档、
输入法服务或系统内核。以下是内部切片规格，不冻结公开包名或 API。

## 真实代码缺口

`src/layout.rs` 的 Taffy 测量回调把可用宽度传给 `TextEngine::measure`，只取回
TextMetrics；该回调可能因布局求解多次执行。`src/paint.rs` 的 DrawText 仅携带
origin/text/font_size/color，没有最终行宽、字体资源身份或布局结果身份。
所以仅替换测量器、在重放时重新创建 Paragraph 仍可能产生测量/绘制断行不一致。
现有 `engine_frame.rs` 的 draw_str 路径也不能作为复杂文字排版交付。

## 最小接入顺序

1. 保留测量求解与最终排版的区别：Taffy 收敛后，按最终 content 宽度生成可供
   绘制消费的同一份布局结果。不得将“最后一次 measure 回调”当成最终布局。
2. 内部布局结果须绑定场景版本、节点代际、文本版本、字体资源代际、字号和最终
   宽度；绘制引用此结果，过期身份拒绝，不凭 text+font_size 缓存猜测节点归属。
3. 固定单 UI 执行上下文，原生 Paragraph 保留在提供它的后端上下文中。批协议
   不序列化 C++ 地址或 Skia 私有结构；远程/其他宿主若无法消费同一结果，必须
   报告能力差异，不能声称布局等价。
4. 注入字体缺失、解析失败、尺寸非法、结果过期须在提交外部帧前拒绝。字体源
   资源关闭与已复制原生字体数据的存活关系须显式登记，不把资源撤销等同强制
   释放第三方所有副本。
5. 一个多行混合文字 Scene 从 Taffy 最终 content 宽度进入 Paragraph，再由该
   Paragraph 绘制；宽度变化触发重排。之后才接编辑提交/预编辑与光标选区。

## 可验收证据与信任边界

自有身份/缓存/提交代码必须先有源码映射 Verus+Z3 规格和拒绝不变性证明，再按
Proptest → Miri → cargo-fuzz → Kani → Loom 顺序验收。单线程路径的 Loom
须给出真实实现适用性说明；以后并发时另行验证。原生 Skia 排版/光栅化和 FFI
作为显式未证明依赖，浮点排版结果不宣称已形式化证明。

行为验收包括最终宽度改变、换字体/字体撤销、旧场景结果拒绝、两节点同文不同宽、
中文/RTL/非 BMP/组合字素、选区单位转换拒绝、同一布局测量与绘制的对应关系。
所有重型构建/验证仅在既有受限 VM，禁止宿主机运行。

既有 `evidence/skia-text-paragraph-cjk` 和 `evidence/skia-text-index-probe` 仅为
原生固定夹具实验，不能勾选上述接入或六阶段验收。本规格也不是功能完成证据。

### 2026-10-24 18:52 UTC：快照借用范围覆盖公开树修改

异步提交，则需独立不可变快照/受控树更新契约和实际证明，不默认现有 version
已覆盖公开字段修改。该条为待实施防错条件，不是已证明或已修复声明。
